# 第四章实验：B+树索引与执行计划

## 实验目标

比较无索引查询、普通 B-tree 索引查询和低选择性条件下的执行计划，理解“创建索引不等于一定使用索引”。

## 准备

建立 `orders(id, customer_id, status, created_at, amount)`，生成足够多的测试数据。记录 PostgreSQL 版本、数据量和统计信息更新时间，保证结果可复现。

## 操作步骤

1. 对 `customer_id` 条件执行 `EXPLAIN (ANALYZE, BUFFERS)`，记录计划节点、估算行数、实际行数和缓冲区访问。
2. 创建 `CREATE INDEX idx_orders_customer ON orders(customer_id);`，重新 ANALYZE 并重复查询。
3. 对只有少数枚举值的 `status` 建索引，比较高频值和低频值。优化器可能对高频值选择顺序扫描，因为读取大量行时索引随机访问未必更便宜。
4. 修改数据分布但暂不更新统计信息，观察估算偏差；执行 ANALYZE 后再次比较。

## 结果解释

不能只用“耗时变短”下结论。需要同时解释数据规模、缓存状态、选择性、估算行数和实际行数。`EXPLAIN ANALYZE` 会真实执行语句，对写语句应放在可回滚事务中谨慎使用。

## 验收产物

提交建表与数据脚本、三组执行计划、对比表和不超过 300 字的结论。结论应说明索引生效条件和本实验不能外推到生产负载的原因。
