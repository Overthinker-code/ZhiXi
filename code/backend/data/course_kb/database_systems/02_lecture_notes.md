# 第三章：事务、并发与恢复

## 事务与 ACID

事务把一组读写操作作为一个逻辑工作单元。原子性要求操作全部生效或全部撤销；一致性要求事务执行前后满足已定义的完整性约束；隔离性约束并发事务之间可见的中间状态；持久性要求提交结果在系统故障后仍能恢复。

转账示例不能只写两条 UPDATE。正确链路至少需要 BEGIN、余额检查、扣款、入账和 COMMIT；任一步失败都应 ROLLBACK。PostgreSQL 官方事务教程明确说明，事务块用 BEGIN 和 COMMIT 包围，ROLLBACK 会取消当前事务中的更新，SAVEPOINT 可以局部回退。

## 并发异常和隔离级别

常见异常包括脏读、不可重复读、幻读和序列化异常。隔离级别不是“越高永远越好”：更强隔离通常降低并发度或增加重试概率。应用必须根据不变量选择隔离级别，并处理序列化失败重试。

在 PostgreSQL 中，Read Uncommitted 按 Read Committed 处理；Repeatable Read 不允许不可重复读，但仍可能因并发更新产生序列化失败；Serializable 提供最强的隔离保证，但应用需要准备重试整个事务。

## MVCC、锁与死锁

MVCC 通过版本可见性让读操作不必总是阻塞写操作，但它不消除所有冲突。对业务不变量敏感的行可使用显式锁或更强隔离。死锁是等待图中出现环；数据库通常终止其中一个事务，应用捕获错误后重试。

## 恢复基本思路

先写日志要求相关日志记录先于脏数据页持久化。恢复时 REDO 用于重放已经提交但数据页尚未落盘的更新，UNDO 用于撤销未提交事务的影响。检查点减少恢复需要扫描的日志范围，但不能替代日志。

## 边界说明

本讲义解释课程原理，并使用 PostgreSQL 18 文档核对产品示例。其他数据库对隔离级别、锁和恢复的具体实现可能不同，回答产品行为时必须标注数据库与版本。
