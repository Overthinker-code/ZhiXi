# 1 引言

## 1.1 编写目的

本说明书用于统一项目组、指导教师、评审人员及后续维护人员对“智屿智能教育平台”的理解，明确系统应当提供的能力、约束与可验证结果。本文既是产品设计与开发依据，也是系统测试、比赛验收、部署交付和后续迭代的基线文档。

## 1.2 项目背景

高校学习场景中普遍存在资源分散、学习反馈滞后、个体差异难以被持续识别、通用大模型回答缺少课程证据等问题。智屿以“课程知识库 + 多智能体协同 + 学生数字画像”为核心，将课程资料、学习行为、练习结果和 AI 交互记录组织为可追踪的学习证据，为学生提供伴学、练习、资源推荐与学习路径，为教师提供课程资源管理、学情分析与课堂辅助能力。

项目以至少一门完整高校专业课程作为系统输入。当前已构建“软件工程导论”课程知识库，资料包括课件、笔记、试题及经审核的外部学习资源，并支持在课程中心统一访问。

## 1.3 产品范围

系统范围包括：

- 用户认证与权限控制；
- 课程中心、课程资源管理与 PPT 放映；
- AI 伴学对话、附件上传、图片识别与课程知识库检索；
- 多智能体任务分工与学习工具调用；
- 题库作答、自动批改、错题本和针对性练习；
- 学情档案、学生数字画像、知识网络和能力成长趋势；
- 个性化学习路径、资源推荐、提醒与悬浮“小智”；
- 教学资料、思维导图、科学图表、PPT 和数字人视频等内容生成；
- 教师工作台与可选的课堂行为分析。

系统不以替代教师作最终教学评价为目标；AI 输出为学习辅助信息，涉及评分、事实引用与外部资源时应保留可核验依据。

## 1.4 读者对象

本文面向参赛评审人员、产品负责人、前后端开发人员、算法工程人员、测试人员、部署运维人员、教师用户及项目验收人员。

# 2 项目概述

## 2.1 产品目标

智屿的总体目标是形成“学习—诊断—规划—资源—练习—反馈”的个人学习闭环：系统从课程资料和真实学习行为中取得证据，由不同智能体完成检索、讲解、批改、规划和画像更新，再把结果反馈为下一步可执行的学习任务。

具体目标如下：

1. 将校内课程资料转化为可检索、可引用、可播放、可练习的结构化知识库。
2. 让 AI 回答优先依据课程材料，降低无依据生成，提高教学场景中的可信度。
3. 持续更新学生画像，识别知识掌握、学习偏好、行为投入和薄弱方向。
4. 通过多智能体协同把复杂请求拆分为可观察、可恢复、可审查的任务链路。
5. 为学生提供从发现问题到巩固练习的闭环，为教师提供可解释的学情依据。

## 2.2 用户角色

| 角色 | 主要目标 | 主要权限 |
|---|---|---|
| 学生 | 学习课程、向 AI 提问、完成练习、查看画像与建议 | 访问已授权课程；上传个人资料；查看本人的对话、错题、画像和学习路径 |
| 教师 | 管理课程资源、了解学情、制作教学内容 | 管理所负责课程与资源；查看授权范围内的班级聚合数据；发起资源生成 |
| 管理员 | 维护用户、服务和系统配置 | 用户与权限管理、运行状态检查、基础配置维护 |
| 外部 AI/内容服务 | 提供文本、多模态、图像或视频能力 | 仅处理后端按任务需要发送的数据，不直接访问平台数据库 |

## 2.3 典型使用场景

### 2.3.1 课程伴学

学生进入“软件工程导论”，选择课件或笔记后向 AI 提问。系统检索课程知识库，返回分层讲解、引用来源和后续追问；对上传的题目截图，系统调用视觉模型识别内容并结合课程上下文解答。

### 2.3.2 错题巩固

学生提交测验后，错题按课程和题目标签自动归类。学生打开某一学科错题本并发起“根据错题生成练习”，练习智能体依据错因、知识点和难度生成变式题，提交后更新掌握证据与画像。

### 2.3.3 个性化学习建议

画像智能体聚合学习记录、练习表现和 AI 交互，形成八维认知模型、知识网络、能力成长趋势和下一步建议；系统可将建议转化为学习路径、资源推荐或“小智”提醒。

### 2.3.4 教学资源生产

教师或学生输入知识主题，系统根据任务类型选择合适能力：课程讲解使用文本模型，图片作业使用视觉模型，结构图使用 Mermaid，科学图表使用程序绘图，场景插图使用图像生成，课件使用结构化内容与 PPT 生成链路。

## 2.4 运行环境

| 类别 | 环境要求 |
|---|---|
| 客户端 | 支持现代标准的 Chrome、Edge 等桌面浏览器，建议分辨率不低于 1366×768 |
| 前端 | Vue 3、TypeScript、Vite；开发端口默认 5174，以实际配置为准 |
| 后端 | Python 3、FastAPI、SQLModel/SQLAlchemy、Alembic；主服务默认端口 8001 |
| 数据库 | PostgreSQL；向量检索采用 Chroma 或兼容实现 |
| 可选中间件 | Redis、Celery，用于异步多媒体任务 |
| 可选算法服务 | YOLO 行为检测、数字人视频生成及兼容 OpenAI 协议的模型服务 |

## 2.5 约束与假设

- 模型密钥必须仅保存在后端环境变量中，不得写入前端包、报告或公开仓库。
- 多模态识别、图像生成和视频生成依赖第三方服务的权限、配额与网络连通性。
- 外部平台资源的可访问性、标题和内容可能变化，系统应展示来源并允许用户离开本站核验。
- 课堂行为分析与数字人渲染属于可选服务，不得阻断学生端核心学习链路。
- AI 评分、画像和推荐均应作为辅助决策，不得在证据不足时伪造确定性结论。

# 3 系统总体架构

## 3.1 逻辑架构

系统采用前后端分离架构。浏览器端负责课程、对话、练习、画像和资源的交互展示；FastAPI 提供认证、业务编排、文件处理和模型访问；PostgreSQL保存业务数据，向量库保存课程切片与检索索引；多智能体运行时根据任务选择检索、批改、练习、规划、画像、资源生成等能力；外部模型与内容服务均由后端统一调用。

```text
学生/教师浏览器
      │ HTTPS / SSE / WebSocket
      ▼
Vue 3 + TypeScript 前端
      │ /api/v1
      ▼
FastAPI 业务与安全网关
 ├─ 用户、课程、资源、测验、错题、画像、学习路径
 ├─ 文件解析、RAG 检索、引用与生成物管理
 └─ 多智能体编排与任务状态
      │
      ├──────────► PostgreSQL / Chroma / 文件存储
      ├──────────► DeepSeek（纯文本处理）
      ├──────────► 通义千问视觉与内容生成能力
      └──────────► 可选 Redis/Celery、YOLO、数字人引擎
```

## 3.2 多智能体协同

平台以课程上下文和学生画像为共享状态，根据任务路由到专业智能体。主要职责如下：

| 智能体/能力 | 主要职责 | 主要输入 | 主要输出 |
|---|---|---|---|
| 课程导师 | 概念讲解、苏格拉底式追问 | 问题、课程证据、对话上下文 | 分层回答、追问、引用 |
| 检索/阅读智能体 | 检索课程与上传文档 | 查询、课程、附件 | 证据片段、摘要、阅读路径 |
| 视觉/批改智能体 | 理解题目图片和学生答案 | 图片、文件、评分要求 | 识别结果、得分点、错因、订正步骤 |
| 练习智能体 | 生成分层题与变式题 | 错题、标签、掌握度 | 题目、反馈、追练 |
| 规划智能体 | 生成可执行学习安排 | 画像、课程进度、待办 | 学习路径、当前任务 |
| 画像智能体 | 聚合学习证据并更新画像 | 对话、练习、资源行为 | 维度评分、趋势、优势与薄弱点 |
| 资源智能体 | 生成讲义、图表、导图、PPT 等 | 主题、课程证据、格式要求 | 可预览、可下载的教学资源 |

## 3.3 关键业务闭环

```text
学习行为与作答
      ↓
形成可追踪证据
      ↓
画像智能体诊断 ──→ 知识掌握与能力趋势
      ↓
规划智能体生成下一步任务
      ↓
推荐资料 / AI 讲解 / 针对性练习
      ↓
新一轮行为与结果再次更新画像
```

# 4 功能需求

本章使用“FR-模块-序号”标识功能需求。“应”表示验收时必须满足，“宜”表示在依赖条件具备时满足。

## 4.1 用户与权限

### FR-AUTH-01 用户登录

系统应支持使用账号和密码登录，登录成功后签发访问凭证，并返回当前用户基本信息。凭证无效、过期或权限不足时，应返回明确但不泄露安全细节的错误。

**验收要点：** 正确账号可进入系统；错误密码不能登录；受保护接口在未认证时拒绝访问。

### FR-AUTH-02 用户资料与密码

用户应能查看和修改本人资料、修改密码；管理员应能在授权范围内管理用户。普通用户不得读取或修改他人的私人学习数据。

### FR-AUTH-03 角色授权

系统应区分学生、教师和管理员权限。教师查看学情时应遵循课程或班级授权边界；学生只能查看本人的画像、错题和学习路径。

## 4.2 课程中心与课程知识库

### FR-COURSE-01 课程浏览

系统应展示用户可访问的课程，支持进入课程工作区并查看课程概览、章节、资源、智能体入口与学习任务。

### FR-COURSE-02 软件工程导论课程

系统应提供“软件工程导论”完整课程入口。初始知识库应包含 PPT、笔记、试题等多类资料，并保留原文件名称、资源类型、知识点、来源和可访问地址。当前课程数据基线为 114 条资源记录，其中包含 82 条 PPT、13 条笔记、13 条练习、3 条哔哩哔哩视频、2 条小红书公开笔记入口及 1 条既有题目资源；数量可随资料更新而变化。

### FR-COURSE-03 资源检索与筛选

用户应能按资源类型、关键词、知识点和课程筛选资源。系统应区分本地课程资料、AI 生成资料与外部网络资料。

### FR-COURSE-04 PPT 放映

系统应支持在课程中心直接预览 PPT/PPTX 资源。若浏览器不能原生解析，后端应将其转换为可放映页面或 PDF；前端应提供上一页、下一页、页码、缩放和全屏能力。转换失败时应提供原文件下载，不得显示空白页面。

### FR-COURSE-05 外部学习资源

系统应能根据学生画像与当前知识点推荐来自公开网络的学习资源，例如哔哩哔哩学习视频和小红书公开笔记入口。每条资源必须展示平台、标题、链接、推荐理由和访问提示；系统不得伪造作者、播放量或内容质量结论。

### FR-COURSE-06 课程知识库索引

系统应对支持解析的课程文件进行文本提取、分段和向量化，使 AI 能按课程范围检索。知识库更新后应能增量写入或重建索引，并记录失败文件。

## 4.3 AI 伴学与多模态输入

### FR-CHAT-01 多轮流式对话

系统应支持创建、查看、重命名和删除对话线程，支持流式显示回答、停止生成、失败重试和保留已生成内容。

### FR-CHAT-02 课程上下文问答

用户选择课程后，AI 应优先使用该课程知识库回答，并将引用片段或来源与正文关联展示。证据不足时应明确说明边界，不得以虚构资料补足答案。

### FR-CHAT-03 图片与文件上传

对话输入区应支持文件选择、剪贴板粘贴和拖放上传。系统应显示附件名称、类型、大小、上传状态，并允许发送前移除。支持范围至少包括常见图片、PDF、文本、Word 和 PPT 文件；不支持的格式应在上传阶段提示。

### FR-CHAT-04 图片内容理解

当附件包含题目截图、手写作业、公式或图表时，后端应把真实图片内容发送给已配置且具有视觉能力的模型，并把识别内容与用户问题一并交给后续智能体。若模型权限、密钥或配额不可用，应返回可理解的配置/服务提示，不能把“已收到附件”当作识别成功。

### FR-CHAT-05 文档内容理解

系统应提取上传文档的可读文本，并允许检索智能体按文档片段回答。回答应区分用户上传材料、课程知识库与外部来源。

### FR-CHAT-06 并发与幂等

同一用户重复点击发送不得产生不可控的重复任务。达到 AI 并发上限时，系统应排队或返回可重试状态，并在前端给出明确提示。

### FR-CHAT-07 划词唤醒边界

划词唤醒宜用于 AI 对话和资料库阅读场景，选择文本后可发起解释、追问或加入对话；在正式做题、考试和作答页面不得出现该能力，以避免泄露答案或干扰作答。

## 4.4 多智能体工作区

### FR-AGENT-01 智能体选择

系统应按课程和任务展示可用智能体，包括资料、科研、陪练、阅读、编写、知识图谱、视频理解、公式识别、作业批改和学习规划等角色。

### FR-AGENT-02 能力边界

每个智能体应声明允许使用的工具、所需输入和输出类型。需要附件的智能体在没有附件时不得伪造识别结果；需要课程上下文的任务应绑定明确课程。

### FR-AGENT-03 任务可观察性

长任务应显示当前阶段、运行时间、进度或状态，支持停止；可恢复任务应记录任务标识和阶段结果，便于失败后重试或继续。

### FR-AGENT-04 深度绑定画像

智能体在得到用户授权后，应读取学生的薄弱知识点、学习偏好、近期目标和历史反馈，用于调整讲解深度、练习难度与资源类型。画像数据的使用应可解释，且不得跨用户混用。

## 4.5 测验、错题本与针对性练习

### FR-QUIZ-01 在线作答与提交

系统应展示题干、选项或答题区域，记录作答并在提交后返回结果。正式作答前不得通过提示、解析或界面元素泄露正确答案。

### FR-QUIZ-02 错题收集

错误作答应进入错题本，保存所属课程、题目、用户答案、正确答案、知识点标签、错误次数、最近作答时间与掌握状态。

### FR-QUIZ-03 智能学科分类

错题本应以“一个学科一本错题本”的形式展示。分类优先使用课程归属和题目标签；标签不足时由练习智能体结合题干与知识点推断，并保留“待确认”状态。系统不得仅将无法匹配的题目长期归入宽泛的“通用课程”。

### FR-QUIZ-04 根据错题生成练习

用户在某一学科错题本中点击“根据错题生成练习”后，系统应选择该学科的代表性错题与薄弱知识点，调用练习智能体生成可作答的变式练习，并跳转或展示对应练习资源。若生成失败，应显示失败原因并允许重试，不得出现按钮无响应。

### FR-QUIZ-05 练习闭环

学生完成错题练习后，系统应更新错题状态、练习记录和学习证据；画像智能体应在后续刷新中反映掌握变化。

## 4.6 学情档案与学生数字画像

### FR-PROFILE-01 学情总览

系统应展示综合能力、近 30 日成长、学习投入和优先提升项，并标明数据更新时间。无足够证据时应展示“待积累”，不能用随机数据填充。

### FR-PROFILE-02 八维认知模型

系统应从知识掌握、学习偏好、学习行为、学习动力、学习目标、认知风格、问题解决能力和知识网络状态等维度形成画像。每个维度应能回溯到一类或多类学习证据。

### FR-PROFILE-03 能力成长趋势

系统应以时间序列展示能力变化，支持总览和分课程查看。趋势点至少包含日期、维度得分、证据量和变化说明；证据不足的时间段应明确为空或低置信度。

### FR-PROFILE-04 知识网络画像

系统应展示课程知识点及前置、包含、关联或易混淆关系，并通过掌握状态区分已掌握、学习中和待提升节点。用户可从节点进入相关资料、练习或 AI 伴学。

### FR-PROFILE-05 画像动态更新

对话、练习、资源学习和任务完成产生的新证据应触发或排队触发画像更新。更新过程应记录版本、时间和主要变化，支持展示“为什么得到该建议”。

### FR-PROFILE-06 分课程查看

系统应按课程聚合掌握情况、30 日变化和当前重点。没有学习证据的课程应显示待学习状态，不应生成虚假掌握度。

## 4.7 学习路径、推荐与“小智”

### FR-PLAN-01 个性化学习路径

系统应根据画像、课程结构、目标和可用时间生成可调整的学习路径，路径节点应包含学习目标、关联课程/知识点、推荐资源、预计任务和完成状态。

### FR-PLAN-02 当前任务

系统应维护用户当前学习任务，允许更新进度、完成或切换任务，并把结果写入学习证据。

### FR-PLAN-03 个性化资源推荐

推荐结果应同时考虑薄弱知识点、学习偏好、内容质量、资源类型和近期重复度。每条推荐应展示推荐理由，并支持打开、忽略或反馈。

### FR-PLAN-04 悬浮“小智”

“小智”应作为全局悬浮胶囊呈现，可采用动态卡通形象与轻量动画。它可根据规划智能体、画像智能体和当前学习任务生成适时提醒，但不得在做题或考试界面主动弹出答案相关内容。

### FR-PLAN-05 提醒控制

用户应能开启或关闭主动提醒，并控制提醒频率。提醒应基于真实任务、薄弱点或学习节奏，避免高频打扰；敏感页面应自动静默。

## 4.8 教学资源与多媒体生成

### FR-GEN-01 任务识别与路由

系统应区分“结构图/思维导图”“科学图表”“场景插图”“PPT”“教学视频”等意图，并选择对应生成链路，不能把所有“生成图片”请求都路由到通用插画模型。

### FR-GEN-02 Mermaid 结构图

知识点思维导图、流程图、数据流图等结构化图形应优先由文本模型生成 Mermaid 代码，并在前端渲染。系统应自动去除多余代码围栏、检查语法并在失败时展示可编辑源码和错误信息。

### FR-GEN-03 科学图表

坐标图、函数图、统计图和协议状态曲线等强调数值或科学关系的图形，应使用受控的 Python/Matplotlib 绘图链路。代码执行应在隔离环境中进行，限制可用库、运行时间、文件路径和网络访问。

### FR-GEN-04 场景插图

历史、地理、语文等不要求精确文字的场景插图，可调用图像生成模型。结果应显示生成提示词与模型信息，并提示生成图片中的文字可能不准确。

### FR-GEN-05 PPT 课件生成

系统应将课程主题与证据转换为结构化课件大纲，并通过程序化排版生成 PPTX。生成物应可预览、下载和继续编辑，引用课程资料时应保留来源信息。

### FR-GEN-06 教学视频

系统宜支持文本或 PPT 生成教学视频。长任务应进入异步队列，显示排队、脚本生成、音频生成、渲染、完成或失败状态，并支持查询结果。

### FR-GEN-07 生成物管理

生成物应关联用户、课程、任务、类型、状态和创建时间；用户可预览和下载已完成文件。失败任务不得返回伪造的成功地址。

## 4.9 教师工作台与课堂辅助

### FR-TEACHER-01 教学概览

教师应能查看所负责课程的学生参与、热门资源、内容类型分布和告警趋势。个人明细必须受权限控制，汇总数据不得泄露无关学生信息。

### FR-TEACHER-02 课堂行为分析

在教师明确启用且满足告知/授权要求时，系统可对图片、视频或实时流进行课堂行为检测，并保存统计结果。该能力应可独立关闭，关闭后不影响课程学习与 AI 对话。

### FR-TEACHER-03 数字人课堂助手

系统宜支持由课堂助手生成讲解或提醒内容，并通过数字人/语音播放；内容应受课程上下文和教师配置约束。

# 5 外部接口需求

## 5.1 用户界面

- 页面应保持统一导航、配色、字号、间距和交互反馈。
- 关键按钮必须具有加载、成功、失败和禁用状态，不能在请求处理中表现为无响应。
- 课程资源、AI 对话、错题本和学情档案应适配常见桌面分辨率。
- 图表应提供图例、单位、时间范围和空状态说明；颜色不应成为唯一信息载体。
- 上传区域应支持点击、粘贴和拖放，并明确文件限制。

## 5.2 后端 API

系统 API 统一以 `/api/v1` 为主要前缀，使用 JSON 交换结构化数据；文件上传使用 `multipart/form-data`；流式对话使用 SSE 或流式 HTTP；实时课堂能力可使用 WebSocket。

关键接口类别包括：

| 类别 | 示例接口 | 说明 |
|---|---|---|
| 认证 | `POST /login/access-token`、`GET /users/me` | 登录与当前用户 |
| 对话 | `POST /chat/stream`、`GET /chat/threads` | 流式回答与线程管理 |
| 文件/RAG | `POST /file/upload`、`POST /rag/upload`、`POST /rag/query` | 附件与知识库 |
| 测验/错题 | `POST /resource-hub/quizzes/{id}/submit`、`POST /resource-hub/wrong-book/practice` | 作答与错题练习 |
| 学情 | `GET /learning-report/me`、`GET /profile/me` | 学情报告与学生画像 |
| 路径 | `GET /learning-path/me`、`GET /learning/current-task` | 个性化路径和任务 |
| 资源生成 | `POST /resource-generation/runs`、`GET /resource-generation/runs/{id}` | 异步生成任务 |
| 运维 | `GET /healthz`、`GET /readyz` | 存活与就绪检查 |

## 5.3 模型服务接口

- 纯文本对话默认通过兼容 OpenAI 协议的 DeepSeek 服务处理。
- 图片理解/作业批改通过具有图像输入能力的通义千问模型处理。
- 结构图使用文本模型生成 Mermaid；科学图表由后端程序绘制；场景插图通过图像生成服务处理。
- 模型调用应设置超时、重试上限、并发限制、错误映射和使用量记录。
- 后端不得把密钥、完整内部提示词或其他用户的上下文返回给前端。

## 5.4 文件接口

上传时应校验扩展名、MIME 类型、大小和文件名，采用服务端生成的安全路径存储；下载时应校验用户权限并设置正确的内容类型。文档预览产生的临时文件应可清理。

# 6 数据需求

## 6.1 核心数据实体

| 实体 | 关键数据 | 关联关系 |
|---|---|---|
| 用户 | 账号、角色、状态、个人资料 | 关联对话、作答、画像、任务与资源 |
| 课程 | 名称、描述、教师、状态 | 包含章节、资源、知识点和测验 |
| 资源 | 标题、类型、文件/链接、来源、知识点 | 属于课程，可被收藏、推荐和引用 |
| 对话线程/消息 | 用户、课程、角色、正文、时间 | 可关联附件、引用、生成物和反馈 |
| 问题/测验 | 题干、选项、答案、解析、标签、难度 | 关联课程、作答和错题 |
| 错题 | 用户答案、错因、错误次数、状态 | 关联题目、用户、课程与练习 |
| 学习证据 | 类型、数值、来源、时间、置信度 | 驱动画像与路径更新 |
| 学生画像 | 八维指标、阶段、优势、薄弱点、版本 | 属于用户，来源于学习证据 |
| 知识节点/边 | 名称、类型、关系、掌握状态 | 关联课程、资源、练习和学习动作 |
| 生成任务/生成物 | 类型、阶段、状态、文件、错误 | 关联用户、课程和智能体任务 |
| 外部推荐 | 平台、标题、URL、理由、审核状态 | 关联用户、课程和知识点 |

## 6.2 数据完整性

- 业务实体应使用稳定唯一标识；关键关联应设置外键或应用层一致性校验。
- 作答、错题、画像和学习路径必须与具体用户关联。
- 画像分数应限制在定义范围内，趋势记录必须包含时间与证据量。
- 删除课程资源时，应明确处理知识库索引、收藏、引用和生成物关联。
- 数据库结构变更应通过 Alembic 迁移管理，不直接依赖手工改表。

## 6.3 隐私与留存

- 仅收集实现学习服务所必需的数据，明确区分身份信息、学习行为、上传材料与课堂视觉数据。
- 用户应能查看本人主要数据；删除账号时应按照产品规则处理关联数据和文件。
- 课堂图片/视频属于高敏感度数据，应遵循告知、授权、最小化保存和限定用途原则。
- 日志不得记录明文密码、完整 API 密钥或无必要的上传文件正文。

## 6.4 备份与恢复

生产环境应定期备份 PostgreSQL 数据库和必要文件。恢复演练应验证用户、课程、资源、作答和画像之间的关联一致性。向量索引可由原始资料重建，但原始资料和索引配置必须保留。

# 7 非功能需求

## 7.1 性能

### NFR-PERF-01 常规接口

在约定测试环境、网络正常且不包含第三方模型等待时间时，95% 的普通查询接口应在 2 秒内返回，普通写入接口应在 3 秒内返回。

### NFR-PERF-02 对话首包

在模型服务可用时，流式对话应在 8 秒内返回状态或首个内容片段；超过时间应持续展示运行状态并允许停止。

### NFR-PERF-03 长任务

PPT、图片和视频等长任务应异步执行，不得占用前端请求直到渲染结束。任务状态查询应在 2 秒内返回。

### NFR-PERF-04 并发控制

系统应对模型调用设置按用户和全局的并发上限，达到上限时排队或返回标准化的“繁忙/稍后重试”响应，而非底层异常文本。

## 7.2 可靠性

- 核心学习功能不得依赖 YOLO、Redis 或数字人等可选服务启动。
- 第三方模型失败时应保留用户输入和已产生内容，允许重试或切换能力。
- 写入型请求应避免重复提交；异步任务应具有唯一标识和明确终态。
- `/healthz` 用于存活检查，`/readyz` 应反映数据库等关键依赖是否就绪。

## 7.3 安全性

- 密码应使用安全哈希存储；认证凭证应有过期时间并通过 HTTPS 传输。
- JWT HMAC 密钥长度应不少于 32 字节，并通过安全随机方式生成。
- 服务端应校验上传文件、下载路径和外部 URL，防止路径穿越、恶意文件和服务端请求伪造。
- 科学绘图或动画代码执行必须隔离，禁止任意系统命令、任意文件访问和未授权网络访问。
- 应对登录、上传、AI 调用和资源生成实施速率限制或配额控制。
- 公开提交前应轮换曾经暴露的第三方密钥，并检查 Git 历史与构建产物。

## 7.4 易用性与可访问性

- 错误提示应使用用户可理解的中文，并给出可执行的恢复动作。
- 加载超过 1 秒的操作应显示进度、骨架屏或运行状态。
- 关键交互支持键盘访问；文本和背景保持可辨识对比度。
- 图表、图标和颜色应配有文字说明；动态“小智”应允许关闭动画与提醒。

## 7.5 兼容性

- 前端支持近两个主要版本的 Chrome 和 Edge。
- 开发和部署应兼容 Windows 与常见 Linux 服务器环境。
- 文档预览应覆盖 PDF、常见图片、文本、DOCX 和 PPTX；无法预览时提供下载降级。

## 7.6 可维护性与可测试性

- 前后端应保持分层结构，模型提供商、课程资源解析和智能体能力通过配置或服务层隔离。
- API 使用明确的请求/响应 Schema，数据库变更通过版本化迁移执行。
- 核心链路至少覆盖认证、课程资源、对话附件、错题练习、画像真实性和生成任务状态测试。
- 日志应包含请求/任务标识、阶段、耗时和标准化错误类别，便于定位问题。

## 7.7 可解释性与 AI 质量

- 课程问答应展示引用；画像建议应展示主要证据；外部推荐应展示来源与推荐理由。
- 视觉识别失败时不得猜测题目；结构图渲染失败时应保留源码和错误；生成任务失败时不得伪装完成。
- AI 输出应经过内容边界检查，明确区分事实、推断与建议。

# 8 运行与部署需求

## 8.1 配置管理

后端配置文件位于 `code/.env`，公开模板位于 `code/.env.example`。模型密钥、数据库密码和 JWT 密钥只配置在运行环境；前端只能获得无敏感信息的 API 地址与功能开关。

## 8.2 启动方式

后端推荐从 `code/backend` 目录执行统一启动脚本：

```powershell
cd C:\Users\Eileen\ZhiYu-main\code\backend
& ..\.venv\Scripts\python.exe .\run_backend_stack.py
```

前端从 `code/education/course` 目录启动：

```powershell
npm run dev
```

Vite 开发代理应将 `/api` 请求转发到 FastAPI 主服务端口 8001。出现 `ECONNREFUSED 127.0.0.1:8001` 时，应首先检查后端是否成功启动及端口配置是否一致。

## 8.3 部署检查

1. 数据库迁移成功且不存在重复 revision。
2. `/api/v1/healthz` 返回存活状态，`/api/v1/readyz` 通过关键依赖检查。
3. 前端生产构建和 TypeScript 类型检查通过。
4. 软件工程导论课程资料已入库，随机抽查 PPT、笔记和练习可访问。
5. 未在前端包、仓库和日志中发现真实密钥。
6. 外部模型不可用时，核心课程浏览和历史学习数据仍可访问。

- 前端生产构建与类型检查通过。
- 后端核心服务测试通过，数据库迁移可重复执行。
- 关键页面不存在按钮无响应、永久加载或未处理异常文本直出。
- 权限测试确认学生不能访问其他学生的画像和错题。
- 安全扫描确认公开文件中无真实 API 密钥、数据库密码和短弱 JWT 密钥。
